## 

Openplace (пишеться з маленької літери) — безкоштовний неофіційний бекенд з відкритим кодом для [wplace.](https://wplace.live) — форк [оригінального openplace](https://github.com/openplaceteam/openplace) (Node.js) мовою Rust, переписаний заради швидкості та загартований проти автоматизації. Ми прагнемо дати всім користувачам свободу та гнучкість, щоб кожен міг створити власний приватний wplace для себе, своїх друзів або навіть своєї спільноти — **на ваших умовах**: вбудований захист від ботів, самостійно розгорнутий фінгерпринтинг і правила спільноти, які можна змінювати на льоту з панелі адміністратора.

Бекенд написаний мовою **Rust** (Axum + Tokio + SQLx) поверх **PostgreSQL** і обслуговує HTTP API wplace з повністю in-memory «гарячим шляхом»: намальовані Tile зберігаються в пам'яті як сітки кольорів і віддаються як PNG з палітровою індексацією, заряди та нагороди нараховуються однією атомарною інструкцією, а статистика регіонів записується у фоновому режимі після відповіді. Це заміна оригінального бекенду на Node.js «з коробки» — ті самі маршрути, ті самі JSON-контракти, ті самі cookie.

## Можливості

- 🤖 **Вбудований захист від ботів та автоматизації** — самостійно розгорнутий фінгерпринтинг, поведінковий аналіз малювання, пов'язування мультиакаунтів і PoW-челенджі. Жодних SaaS, жодних даних, що залишають ваш сервер
- 🦀 **Rust (Axum + Tokio + SQLx)** — багатопотоковий HTTP-сервер із низькою затримкою
- 🖼️ **In-memory рушій Tile** — «гарячі» Tile живуть в оперативній пам'яті (кожна — сітка кольорів на 1 МБ) і віддаються як PNG з палітровою індексацією, без звернення до БД на кожен запит
- ⚡ **Атомарний конвеєр малювання** — регенерація зарядів, перевірка достатності, нагороди за рівень і Droplets в одній інструкції `UPDATE … RETURNING`; пакетне оновлення пікселів; відкладений запис блобів Tile і статистики регіонів
- 🗺️ **Регіони GeoNames** — пошук найближчого регіону через KD-дерево з мемоізацією на піксель, таблиці лідерів за регіонами та країнами, автодоповнення
- 🏆 **Таблиці лідерів** — гравці / альянси / країни / регіони за сьогодні / тиждень / місяць / весь час, materialized views + регіонові таблиці в реальному часі
- 🛡️ **Інструменти модерації** — тікети зі скріншотами, бани з каскадом за діапазонами IP, таймаути, панелі адміністратора та модератора, імпорт списку заблокованих IP
- 🛒 **Крамниця та прогресія** — валюта Droplets, заряди, платна палітра, 251 прапор, рівні
- 💬 **Інтеграція з Discord** — OAuth-прив'язка, посилення кулдаунів за ролями, gateway-бот, сповіщення в особисті повідомлення
- 🔐 **Сесії та автентифікація** — JWT у cookie, паролі bcrypt, кеш сесій у пам'яті, обмеження запитів на IP
- 🐘 **PostgreSQL 17** — upsert через `ON CONFLICT`, статистичні ключі `UNIQUE NULLS NOT DISTINCT`, паралельна агрегація

## Продуктивність

Однаковий синтетичний набір даних (1 000 регіонів, 5 000 користувачів, 20 Tile × 250 тис. намальованих пікселів = 5 млн рядків), обидва стеки на одній машині, бази даних у Docker, той самий HTTP-генератор навантаження (прогріті keep-alive-з'єднання, прогони по 20 с). Числа з дев-хоста під Windows 11 — важливі насамперед **пропорції**:

| Сценарій (паралелізм) | Node.js + MariaDB | Rust + PostgreSQL | Прискорення |
|---|---|---|---|
| `GET /health` — накладні витрати фреймворку (64) | 10,315 rps · p50 5.8 ms | **135,448 rps · p50 0.43 ms** | **13×** |
| `GET /files/s0/tiles/0/0.png` — гаряча Tile (32) | 434 rps · p50 71.9 ms | **9,412 rps · p50 2.95 ms** | **22×** |
| Змішане читання (32) | 521 rps · p50 60.6 ms | **5,177 rps · p50 0.85 ms** | **10×** |
| `GET /s0/pixel/…` — інформація про піксель (32) | 3,202 rps · p50 9.4 ms | **6,445 rps · p50 4.7 ms** | 2× |
| `GET /me` — профіль з автентифікацією (50) | 2,063 rps · p50 23.7 ms | **7,224 rps · p50 6.6 ms** | 3.5× |
| `GET /leaderboard/player/all-time` (32) | 2,983 rps · p50 9.9 ms | 4,094 rps · p50 7.1 ms | 1.4× |
| `POST paint`, 25 пікселів (50 паралельно) | 4.5 rps · **45% 5xx** · p50 8.9 s | **434 rps · 0 помилок · p50 111 ms** | **~97×** |
| `POST paint`, 25 пікселів (8 паралельно) | 4.2 rps · p50 2.0 s | **401 rps · 0 помилок · p50 18.4 ms** | **~95×** |

У перерахунку на пропускну здатність малювання: старий стек витримує ~105 намальованих пікселів/сек під конкуренцією, а стек на Rust — **~10 000 намальованих пікселів/сек** без жодного збою. За 50 одночасних «художників» бекенд на Node починає повертати HTTP 500 (конфлікти запису Prisma на «гарячому» рядку користувача), а затримка виростає до секунд — бекенд на Rust тримає p99 нижче 270 мс.

### Чому це структурно краще — а не просто швидше

Швидкість — це симптом, а не мета. Переписування усуває цілі класи проблем, з якими стикається бекенд на Node.js + ORM під масштабуванням:

| | Оригінал на Node.js | openplace (Rust) |
|---|---|---|
| Транзакція малювання | багатокрокова транзакція Prisma, `SELECT … FOR UPDATE`, цикли повторних спроб, під навантаженням потрібні налаштовувані таймаути | одна атомарна інструкція `UPDATE … WHERE charges_left >= cost RETURNING` — немає чому вичерпувати таймаут |
| Конвеєр Tile | при кожному малюванні: decode → canvas → повторна квантизація sharp, блоб перезаписується з БД | сітка кольорів у RAM — джерело істини; індексований PNG перекодовується за ~1–3 мс; самовідновлюваний reconcile-цикл перебудовує будь-яку Tile, чиї піксельні рядки новіші за її блоб (безпечний до збоїв) |
| Навантаження на БД за запит | сесія + користувач перечитуються з БД на кожному запиті | TTL-кеші для сесій, користувачів, регіонів, налаштувань |
| Docker | npm install + prisma generate/db push під час старту контейнера, проксі стартує раніше за готовність застосунку | єдиний статичний бінарник, вбудована перевірка healthcheck, Caddy чекає здорового застосунку |
| Захист від ботів | відсутній | самостійний фінгерпринтинг + поведінкове оцінювання + PoW (див. вище), налаштовується на льоту |

## Швидкий старт (Docker)

Вимоги: [Docker](https://docs.docker.com/get-docker/) з Compose v2.

```sh
# 1. Клонуйте разом із фронтенд-субмодулем
git clone --recurse-submodules https://github.com/13MrBlackCat13/openplace.git
cd openplace

# 2. Налаштуйте
cp .env.example .env
# → відкрийте .env і задайте JWT_SECRET (обов'язково) та все інше, що потрібно

# 3. Запустіть
docker compose up -d --build
```

Потім ініціалізуйте базу даних та імпортуйте дані регіонів:

```sh
# створити таблиці + системних користувачів
docker compose exec app openplace-backend setup

# імпортувати дані міст GeoNames (див. «Дані регіонів» нижче)
docker compose exec app openplace-backend import-geonames /path/to/cities1000.zip
```

API слухає на `:3000` (за Caddy на `:80`/`:443`), Nuxt-фронтенд — на `127.0.0.1:3001`.

> [ПОРАДА]
> `setup`, `import-geonames` та інші — це підкоманди єдиного
> бінарника `openplace-backend` — див. [довідник командного рядка](#довідник-командного-рядка).

## Встановлення з вихідного коду

Вимоги: [Rust](https://rustup.rs/) 1.85+, [PostgreSQL](https://www.postgresql.org/) 15+ (рекомендовано 17), опційно [Caddy](https://caddyserver.com/) для TLS/зворотного проксі.

```sh
git clone --recurse-submodules https://github.com/13MrBlackCat13/openplace.git
cd openplace

# 1. База даних
createdb openplace            # або через Docker: docker run -d --name openplace-pg \
                              #   -e POSTGRES_DB=openplace -e POSTGRES_USER=postgres \
                              #   -e POSTGRES_PASSWORD=password -p 5432:5432 postgres:17-alpine

# 2. Змінні середовища
cp .env.example .env
# → задайте DATABASE_URL="postgres://postgres:password@localhost:5432/openplace"
# → задайте JWT_SECRET — довгий випадковий рядок

# 3. Збірка та запуск
cd backend-rs
cargo run --release -- setup          # міграції + системні користувачі
cargo run --release -- import-geonames cities1000.zip
cargo run --release -- serve          # HTTP API на BACKEND_PORT (за замовчуванням 3000)
```

> [ПРИМІТКА]
> Сервер роздає каталог `frontend/` (git-субмодуль) як статичні файли,
> визначаючи його через `FRONTEND_DIR` (за замовчуванням `./frontend`)
> **відносно робочого каталогу, з якого його запущено**. Якщо ви запускаєте
> бінарник із `backend-rs/`, задайте `FRONTEND_DIR=../frontend`.

### Дані регіонів

Межі регіонів і міста взяті з дампу [GeoNames](https://download.geonames.org/export/dump/). Завантажте один із файлів — `cities500.zip` (найменший), `cities1000.zip`, `cities5000.zip` або `allCountries.zip` (найбільший) — та імпортуйте його: імпортер приймає і `.zip`, і сирий TSV:

```sh
openplace-backend import-geonames cities1000.zip
```

Без даних регіонів бекенд також працює, але кожен піксель потрапляє до резервного регіону.

## Конфігурація

Уся конфігурація — через змінні середовища (`.env`). Повний анотований список — у [.env.example](https://github.com/13MrBlackCat13/openplace/blob/main/.env.example); найважливіше:

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `DATABASE_URL` | — | Рядок підключення до PostgreSQL (**обов'язково**) |
| `JWT_SECRET` | — | Секрет підпису HS256 (**обов'язково**) |
| `BACKEND_PORT` | `3000` | HTTP-порт (також враховується `PORT`) |
| `EXTERNAL_URL` | — | Публічна базова URL-адреса (використовується в посиланнях на скидання пароля) |
| `COOLDOWN_MS` | `30000` | Базовий інтервал відновлення заряду |
| `LEVEL_BASE_PIXEL` / `LEVEL_EXPONENT` | `30` / `0.65` | Крива рівнів: `(pixels/30)^0.65 + 1` |
| `ENABLE_RATE_LIMIT` | `false` | Увімкнути обмеження запитів на IP |
| `*_RATE_LIMIT_ATTEMPTS` / `*_RATE_LIMIT_MS` | див. `.env.example` | Ліміти для входу/реєстрації/скидання пароля/малювання |
| `BAN_ON_BANNED_IP` / `BLOCK_TOR` | `false` | Банити акаунти, що малюють із заблокованих IP / блокувати вихідні вузли Tor |
| `DISCORD_*` | — | Інтеграція OAuth + бот (опційно) |
| `DB_MAX_CONNECTIONS` | `32` | Розмір пулу з'єднань PostgreSQL |
| `SESSION_CACHE_TTL_MS` | `60000` | Як довго сесії перевіряються з RAM |
| `USER_CACHE_TTL_MS` | `30000` | TTL кешу рядка користувача |
| `TILE_CACHE_MAX_TILES` | `512` | Скільки намальованих Tile залишаються в RAM |
| `TILE_FLUSH_MS` / `STATS_FLUSH_MS` | `500` / `1000` | Інтервали відкладеного запису блобів Tile і статистики |
| `FRONTEND_HOST` / `FRONTEND_PORT` | `localhost` / `3001` | Ціль проксі Nuxt-фронтенду |
| `FRONTEND_DIR` | `./frontend` | Каталог статичного фронтенду (відносно cwd) |
| `ANTI_BOT_MODE` | `log` | `off` / `log` / `enforce` — вбудований захист від ботів |
| `ANTI_BOT_KEY` | похідний від `JWT_SECRET` | Ключ HMAC для ідентифікаторів відвідувачів |
| `ANTI_BOT_POW_BITS` | `18` | Складність proof-of-work |
| `ANTI_BOT_ENFORCE_THRESHOLD` | `100` | Бал, що блокує малювання в режимі `enforce` |

## Довідник командного рядка

`openplace-backend` — єдиний бінарник із підкомандами:

| Команда | Опис |
|---|---|
| `serve` | Запустити HTTP-сервер (основне навантаження) |
| `setup` | Застосувати міграції та створити системних користувачів |
| `import-geonames <file.zip\|file.txt>` | Імпортувати дамп GeoNames як регіони |
| `import-ip-list <file> [--reason ip-list]` | Імпортувати заблоковані IP/CIDR (по одному на рядок, коментарі `#`) |
| `system-notification <title> <message>` | Розіслати системне сповіщення всім користувачам |
| `redraw-tiles` | Перемалювати всі PNG Tile з піксельних рядків |
| `init-leaderboard` | Ініціалізувати подання таблиць лідерів |
| `migrate-from-mysql <mysql-url> [--force]` | Імпортувати дані зі старої бази Node.js |
| `seed-bench` | Наповнити базу синтетичними даними для навантажувального тестування |

## Міграція зі старого бекенду на Node.js

Перенести наявну спільноту зі стеку Node.js/MariaDB можна однією командою. Паролі (bcrypt) і навіть активні сесії входу переносяться — якщо `JWT_SECRET` не змінено, користувачі залишаться в системі.

```sh
# 1. Розгорніть новий бекенд (див. «Встановлення з вихідного коду»)
openplace-backend setup

# 2. Імпортуйте все зі старої бази MariaDB/MySQL
DATABASE_URL="postgres://…new…" \
  openplace-backend migrate-from-mysql "mysql://root:password@old-host:3306/openplace"

# 3. Запустіть новий бекенд
openplace-backend serve
```

Що переноситься: **користувачі** (з хешами паролів), **пікселі**, **PNG-блоби Tile**, **альянси** (учасники, запрошення, бани), **улюблені локації**, **заблоковані IP**, **регіони**, **тікети** (зі скріншотами), **нотатки про користувачів**, **подання таблиць лідерів**, **статистика регіонів**, **сповіщення**, **аватарки** та **сесії**. ID зберігаються.

Імпортер відмовляється писати в непорожню цільову базу, якщо не передати `--force`; повторний запуск безпечний (виконується upsert).

## Захист від ботів та автоматизації (вбудований, самостійний)

Оригінальний wplace покладається на платний SaaS для фінгерпринтингу. openplace постачає еквівалент, який **повністю належить вам**: жодних сторонніх сервісів, жодних даних, що залишають ваш сервер, а кожен шар можна перемикати з панелі адміністратора на `/admin/customize` — без перезапусків.

| Шар | Що робить | Працює без JS? |
|---|---|---|
| **Збирач фінгерпринтів** | Автономний скрипт (`/fp.js`) автоматично впорскується в кожну сторінку, яку роздає сервер — змін фронтенду не потрібно. На клієнті хешує ознаки canvas / WebGL / аудіо / шрифтів; сервер виводить стабільний **ідентифікатор відвідувача** (`HMAC-SHA256` із серверним ключем — клієнт не може його підробити). | частково |
| **Пов'язування мультиакаунтів** | Один ідентифікатор відвідувача, що малює з кількох акаунтів, показується адміністраторам у `/admin/users` (`fp_accounts`, `fp_linked_users`). Живить правило `ALLOW_MULTI_ACCOUNT`. | ні |
| **Поведінкове оцінювання** | Кожен запит на малювання спостерігається на сервері: механічно рівні інтервали між запитами, ідеально однакові розміри батчів, UA автоматизації (`HeadlessChrome`, `Puppeteer`, `python-requests`, `navigator.webdriver`), відсутні фінгерпринти. | **так** |
| **Челендж proof-of-work** | Позначені користувачі скидають свій бал, розв'язавши SHA-256 PoW (`/fp/challenge`) — справжні користувачі цього не помічають; ферми скриптів спалюють CPU. | так |

### Сигнали, що підвищують бал бота користувача

| Сигнал | Вага |
|---|---|
| Механічно рівні інтервали малювання (коефіцієнт варіації < 0.08) | +40 |
| Ідеально однакові розміри батчів у багатьох запитах | +25 |
| Headless / автоматизаційний user agent, `navigator.webdriver` | +60 |
| Великий обсяг малювання без жодного зібраного фінгерпринта | +20 |

### Застосування

`ANTI_BOT_MODE` — `off` / `log` (за замовчуванням: спостереження, бали видимі адміністраторам) / `enforce`: користувачі з балом вище `ANTI_BOT_ENFORCE_THRESHOLD` отримують 403 на малювання, доки не розв'яжуть PoW. Адміністратори та модератори завжди звільнені. Усе це редагується на льоту в `/admin/customize` — включно з переходом у `enforce` посеред атаки. Якщо `ALLOW_BOTS=true` (правила спільноти), залишайте `log`: ботні спільноти залишаються видимими, але ніколи не блокуються.

> [ПРИМІТКА]
> Жоден фінгерпринтинг не переможе рішучого супротивника зі stealth-автоматизацією браузера — захист тут підвищує вартість масової автоматизації та робить її видимою для модераторів, а систему доповнюють заряди, скарги та каскади IP-банів. Зберігаються лише похідні хеші та грубі поля (без сирих даних canvas/аудіо), тож обсяг збережених даних мінімальний.



### Робота за Cloudflare

Бекенд визначає IP клієнта точно так, як оригінальний бекенд на Node: `cf-connecting-ip` → `x-forwarded-for` (перший запис) → адреса сокета. IP-бани, ліміти запитів і статистика прив'язуються до цього визначеного IP, тож усе працює «з коробки» за Cloudflare (або будь-яким зворотним проксі, що виставляє ці заголовки).

> [ВАЖЛИВО]
> Ці заголовки довіряються безумовно (як і в оригінальному бекенді), тож прямий доступ до origin має бути заблокований — інакше клієнт може підробити `cf-connecting-ip` та обійти IP-бани / ліміти запитів. Обмежте порт 3000 діапазонами IP Cloudflare або поставте попереду Caddy / Cloudflare Tunnel.

## Бенчмарки: як ми вимірювали

Генератор навантаження постачається разом із бекендом (`backend-rs/src/bin/loadgen.rs`) — відтворіть таблицю вище так:

```sh
# наповніть обидва стеки однаковими даними
DATABASE_URL="postgres://…" backend-rs/target/release/openplace-backend seed-bench \
  --regions 1000 --users 5000 --tiles 20

# навантажте будь-який зі стеків (приклад)
backend-rs/target/release/loadgen --url http://127.0.0.1:3900 \
  --scenario tile --tile 0,0 --conns 32 --duration 20
backend-rs/target/release/loadgen --url http://127.0.0.1:3100 \
  --scenario paint --paint 25 --logins 50 --conns 50 --duration 20
```

Примітки щодо чесності порівняння: ендпоінт таблиці лідерів обмежений тим самим агрегатним SQL, який виконують обидва стеки, звідси скромні 1.4×; числа малювання включають синхронний коміт у БД (списання зарядів є довговічним в обох стеках до надсилання відповіді).

## Додавання перекладу

> [ПОПЕРЕДЖЕННЯ ⚠️]
> Внески, зроблені за допомогою штучного інтелекту, будуть відхилені, і вас **БУДЕ** заблоковано в репозиторії. Ви повинні досконало володіти мовою, яку перекладаєте.

Щоб зробити внесок у цей репозиторій і перекласти `README.md` та інші файли встановлення, дотримуйтеся наведених нижче кроків.

### Змініть номер версії вгорі цього README, щоб вказати, що додано нову мову

Номер версії має формат `X.XX`, де перша «X» позначає кількість мов, офіційно перекладених на цей момент. Другий набір «X» після крапки змінюється щоразу, коли вносяться будь-які зміни до англійської версії README.
Цей номер версії допомагає перекладачам знати, коли їм потрібно оновити вже перекладений контент.

### Створіть нову папку в каталозі `translations`, назвавши її за ISO-кодом вашої мови

Якщо ви не впевнені, який у вас ISO-код, перевірте його [тут](https://gist.githubusercontent.com/josantonius/b455e315bc7f790d14b136d61d9ae468/raw/416def351bc1f790d14b136d61d9ae468/language-codes.json) або просто пошукайте в Інтернеті. Вам потрібен дволітерний код, наприклад `en` для англійської.

### Скопіюйте англійські файли до нової папки

Скопіюйте англійські файли з папки `translations` та головний `README.md` до щойно створеної папки.
Тепер у вас має бути чотири файли: `README.md` та три markdown-файли з інструкціями встановлення (`.md`).

### Додайте правильний прапор до обох README

Створюючи новий переклад, ви маєте оновити **два** файли README:

#### 1. **Оригінальний англійський README**

Додайте вгорі **лише прапор країни/мови, на яку ви перекладаєте**.
Цей прапор має посилатися на ваш новий перекладений README.

Використайте цей шаблон:

```html
<a href="translations/LANGUAGE_ISO_CODE/NAME_OF_YOUR_README.md"><img src="https://flagcdn.com/256x192/LANGUAGE_ISO_CODE.png" width="48" alt="NAME_OF_COUNTRY Flag"></a>
```

Замініть заповнювачі ISO-кодом і назвою країни для вашого перекладу.

#### 2. **Ваш перекладений README**

Вгорі вашого перекладеного README додайте **лише американський прапор**, що посилається назад на англійський README.

> [ПОПЕРЕДЖЕННЯ ⚠️]
> Прапори в англійському README мають залишатися в алфавітному порядку за ISO-кодом.

### Оновіть посилання в розділі «Початок роботи»

У розділі **Початок роботи** оновіть посилання так, щоб вони вказували на ваші перекладені файли.
Якщо ви не впевнені, як це зробити, зверніться до папки іншої мови (наприклад, `fr`).
